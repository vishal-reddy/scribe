# Scribe System Architecture

Scribe's architecture employs an edge-first, reactive design pattern built entirely on Cloudflare's serverless primitives.

## Architectural Layers

| Layer | Implementation | Purpose |
|---|---|---|
| **Edge Gateway** | `src/index.ts`, `src/routes/` | HTTP request routing, CORS negotiation, Kinde JWT verification, and rate limiting |
| **Real-time Sync** | `src/durable-objects/DocumentSync.ts` | State machine maintaining active Yjs binary updates and broadcasting diffs over hibernatable WebSockets |
| **Persistence** | `src/db/`, `migrations/` | Schema management, D1 queries for documents, tags, organization workspaces, and audit logs |
| **Storage Quota Subsystem** | `src/lib/quota.ts` | Cumulative multi-app storage quota computation, enforcing the 50 MB threshold before mutations |
| **Agent Toolset** | `src/mcp/` | Model Context Protocol endpoints exposing structured document operations to AI assistants |

## Technology Choices

- **Runtime**: Cloudflare Workers (`nodejs_compat` enabled).
- **CRDT Engine**: Yjs (`yjs`, `y-protocols`).
- **Database**: Cloudflare D1 SQLite database (`scribe-db`).
- **Auth Provider**: Kinde (`https://kecker.kinde.com`) with sub ↔ email canonical alias resolution.
- **Quota Coordination**: Real-time cross-worker KV and HTTP synchronization with `mcp.kecker.co`.
